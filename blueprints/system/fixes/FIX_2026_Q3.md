### FIX-20260716-005
- **Date**: 2026-07-16
- **Author**: cursor-agent
- **IC Review**: 投委会 (Investment Committee) — 2026-07-16 full architectural critique + approval
- **Commit**: (pending)
- **Type**: fix
- **Module**: runtime-live, execution
- **Files**: core/runtime/live_cycle.py, core/runtime/position_close_adapter.py, scripts/mt5_bridge_worker.py
- **Description**: L3: Permanent zombie/ghost position fix — 军令状 (military pledge). **Four-layer defense-in-depth with three-layer in-flight order protection (per 投委会 review):**

  **Core Defense (4 layers):**
  (1) **Pre-management MT5 sync** (`live_cycle.py`): before each management phase, verify all position_manager positions against MT5 broker ground truth, clear zombies immediately — closes the race window where bridge-direct close writes escape reconciliation and management_phase dispatches modify_sltp on dead positions → bridge detects position_already_closed_recovered → ghost close entries accumulate.
  (2) **Periodic zombie detection loop** (`live_cycle.py`): every 10 cycles, verify ALL known_open_tickets against MT5 positions_get() — catches zombies that evade both reconciliation dedup and pre-management sync; also detects orphan MT5 positions not tracked in known_open_tickets.
  (3) **Bridge journal _source provenance** (`mt5_bridge_worker.py`): all bridge-written journal entries tagged with `_source` field — `bridge` for normal writes, `bridge_position_already_closed_recovered` for ghost-close recovery events — enabling audit attribution of all 84 historical recovered events.
  (4) **PositionCloseAdapter _source tagging** (`position_close_adapter.py`): adapter-mediated close entries tagged `_source: mt5_reconciliation` — enables `_append_journal()` dedup to correctly supersede bridge-direct writes, restoring the downstream notification chain (position_manager.clear_position, reentry_guard, pnl_ledger).

  **In-Flight Order Protection (投委会追问 — 3 sub-layers within §1 & §2):**
  G1. **MT5 None/empty guard**: Skip zombie clear if `positions_get()` returns None (API error), timeout sentinel, or empty list while position_manager has active positions — prevents false zombie detection during MT5 internal sync gaps or restarts.
  G2. **Position age gate** (`_MIN_POSITION_AGE_CYCLES = 2`): Only clear positions that have survived ≥ 2 full cycles since `entry_cycle`. A brand-new position opened in the last cycle may not yet appear in `positions_get()` due to MT5 propagation delay — this gate prevents killing live in-flight orders.
  G3. **Young-position deferral**: Positions below the age threshold that are absent from MT5 are logged as `pre_mgmt_zombie_deferred_young` / `zombie_detection_deferred_young` and re-checked next cycle — no silent drops, full audit trail.

  **Root cause chain**: L3 architecture defect (known_open_tickets ≠ position_manager.active_positions ≠ MT5, no single truth source) + L2 logic defect (bridge wrote close entries directly via _append_journal() bypassing PositionCloseAdapter.record() → no downstream notification; reconciliation dedup then blocked adapter from writing corrected data → _notify_position_manager() never called → position_manager held stale positions → management_phase dispatched modify_sltp/close on dead positions → bridge detected position_already_closed_recovered → 84 ghost events).
- **Root Cause**: L3 — architecture defect: position lifecycle had three independent data structures with no cross-cycle synchronization; L2 — logic defect: bridge→journal write path bypassed PositionCloseAdapter notification chain, and dedup blocked adapter from ever catching up
- **Prevention**: Multi-layer active defense against broker ground truth (not passive journal dedup). Pre-management sync (every cycle) + zombie detection (every 10 cycles) + _source provenance chain (every journal entry) + in-flight order protection (age gate + MT5 empty guard). Any future close path that writes directly to journal will be caught by the zombie detection loop within 10 cycles — the safety net is architectural, not procedural. 投委会 final assessment: "逻辑极其纯净，防御变被动为主动，直击状态机底层。全优放行。"
- **Dependents Checked**: management_phase.py (pre-management sync runs BEFORE management phase), reconciliation.py (PositionCloseAdapter _source tag compatible with existing dedup logic), journal_cleanup.py (_append_journal dedup chain verified compatible), restart_state.py (bootstrap path unaffected), ActivePosition.entry_cycle (age gate uses existing field, no schema change)
